# 장단 Phase 1 구현 계획 (2026-09-05)

기획서 v2(`docs/plan-2026-09-05-v2.html`) 08절 Phase 1 범위를 코드 단위로 쪼갠 것. 이 문서가
병렬 위임 라운드의 **공통 계약 원본**이다 — 각 라운드 스펙은 여기의 해당 절을 인용한다.
스파이크 게이트(Phase 0)는 5분 언더런 1건만 남기고 전부 통과했으므로 스파이크 코드는 동결하고
(`spike/`는 계측 페이지로만 유지) 제품 코드는 새 위치에 쓴다.

## 1. 아키텍처

```
engine/    순수 Go DSP+시퀀서. TinyGo wasm-unknown → AudioWorklet. 명령(Cmd)으로만 조작.
session/   순수 Go. 이벤트 로그·키프레임·시드 단어·URL 직렬화. 메인 스레드(UI wasm)에서 돈다.
resident/  순수 Go. 오토파일럿: 생성기·에너지 곡선·바이브·포모도로. Cmd를 내놓는다.
cmd/worklet/  TinyGo 진입점(export 표는 §3).  cmd/render/ 네이티브 렌더·해시.  cmd/jdsess/ URL 길이 측정.
app/       Ebitengine(GOOS=js). core/(공용 컨텍스트) view/device/ view/room/ main.go(배선).
app/web/   index.html · host.js(워클릿 호스트·로그·리플레이·텔레메트리) · processor.js · wasm_exec.js
cf/        리포트·텔레메트리 수신 Worker(있음).  tools/  게이트·배포·fal 파이프라인.
```

원칙: **로그가 정본.** 사람 손이든 레지던트든 엔진에 닿는 모든 변경은 `engine.Cmd` 하나로 통일되고,
호스트가 `(블록 인덱스, Cmd, 저자)`로 기록한다. 리플레이·URL 열기·서버 렌더는 전부 "새 엔진 + 같은 로그".
레지던트는 재생하지 않는다(그 출력이 이미 로그에 있다). 엔진은 파라미터를 12비트로 정규화해 저장하므로
로그·키프레임의 uint16이 곧 엔진 값이다(직렬화 왕복에 반올림 오차 0).

## 2. 엔진 계약 (`engine/`) — 리드 소유 파일: engine.go · params.go · cmd.go · state.go · approx.go

### 2.1 파라미터 (`params.go`, 전부 0..1, 엔진이 4095 단계로 양자화)

| ID | 이름 | 매핑 |
|---|---|---|
| 0..7 | BassA: Tune, Cutoff, Reso, EnvMod, Decay, Accent, Wave, Oct | Tune ±12반음(0.5=0) · Cutoff 200Hz..8kHz 지수 · Reso 0..자기발진 직전 · EnvMod 0..4옥타브 · Decay 30ms..2s 지수 · Accent 깊이 · Wave <0.5 톱니 ≥0.5 사각 · Oct 3단(−1/0/+1) |
| 8..15 | BassB: 같은 8개 | 같음 |
| 16..27 | BD·SD·CH·OH·CP·CY 각 Level, Tune | Level 선형 · Tune ±(보이스별 정의) |
| 28 | Delay | 0=꺼짐 · 믹스와 피드백을 한 노브에(믹스 0..0.5, 피드백 0..0.7) · 시간은 템포 동기 점8분 |
| 29 | Drive | 0..1 → 프리게인 1..8, 유리식 소프트클립 |
| 30 | Comp | 사이드체인 깊이 0..1(킥 트리거 → 베이스 게인 덕킹, 릴리즈 120ms) |
| 31 | Master | 0..1 선형, 기본 0.8 |
| 32 | Tempo | 100..160 BPM, 기본 130(=0.5) |

기본값은 `DefaultParams()`가 소유한다(전부 0.5가 아니다 — 표에 있는 기본 참조).

### 2.2 파트·명령 (`cmd.go`)

```go
Part: BassA=0 BassB=1 BD=2 SD=3 CH=4 OH=5 CP=6 CY=7 (NumParts=8)
Cmd{Kind, A, B, C, D uint8; V float32}
  SetParam      A=ParamID              V=값
  BassStep      A=Part(0|1) B=step C=note(0..36, 24=C3 기준 반음) D=flags(bit0 gate, bit1 slide, bit2 accent)
  DrumStep      A=Part(2..7) B=step  D=flags(bit0 on, bit2 accent)
  SelectPattern A=Part(0|1) B=slot(0..7)      — 다음 바 경계에 적용
  Mute          A=Part B=on(0|1)
  Trigger       A=Part(2..7)                  — 패드 즉시 원샷
  Drop                                        — 다음 바 경계에 발동(§2.5)
  ResetPos                                    — 스텝 0·바 0으로(리플레이 시작용)
  SetKey / SetChord / BassMode / Transport    — §12.1
  AddDevice     A=slot(0..15) B=DeviceKind    — 장치 그래프(§14.1, rack.go). 실패(점유·범위 밖·인스턴스 고갈)는 무동작
  RemoveDevice  A=slot                        — 닿는 케이블 전부 제거(Main 불가)
  Connect       A=src B=dst C=srcPort|dstPort<<4 D=bind(ParamID; ≥NumParams=비결속) V=게인(비결속) — 순환·포트 범위 밖 거부
  Disconnect    A=src B=dst C=ports
  DeviceParam   A=slot B=k(0..7) V            — 장치 로컬 파라미터(양자화 저장 — 종류가 해석, KindPoly부터)
  DeviceStep    A=slot B=step C=note D=flags   — 장치별 스텝 패턴(게이트·액센트; 종류가 해석)
```
`Apply(Cmd)`는 무할당·클램프(범위 밖은 정규화, 무시하지 않는다: step&15, part 범위 밖은 무동작).

### 2.3 상태 (`state.go`)

`StateSize` 바이트 고정(v5 = 1936, 'J','5'): params[59]u16 · bass 패턴 2파트×8슬롯×16스텝×(note u8, flags u8) · drum 6×16 flags ·
선택 슬롯 2 · 뮤트 비트 1 · 키·모드·트랜스포트·코드 트랙(§12) · **랙**(슬롯 종류 16 · 인스턴스 16 · 케이블 수 · 케이블 64×6 ·
장치 로컬 파라미터 16×8 u16 · 장치 스텝 패턴 16×16×2). `WriteState(dst) int` / `ReadState(src) bool`(길이·범위 재정규화, 실패 시 false — 랙은 빈 랙에서
슬롯·케이블을 다시 놓으며 정규화, 결속 게인은 파라미터에서 재유도, v4 이하 매직 거부).
보이스 내부 상태(필터 메모리·엔벨로프)는 포함하지 않는다 — 키프레임은 **바 경계의 제어 상태**이고 복원은 바 경계에서만.

### 2.4 시계·신호

`Render(out []float32)`(256 float32, 1블록) 후 읽기: `Block() uint64` · `Step() int` · `Bar() uint32` ·
`Flags() uint32`(직전 블록: bit part=트리거, bit8 바 경계, bit9 드롭 발동, bit10 액센트 트리거) · `Peak() float32`.
`Reset(seed)` — 무할당 재초기화(-gc=leaking에서 `New` 재호출 금지).

### 2.5 DROP

`Drop` 명령은 다음 바 경계에 발동: 전 파트 뮤트 해제, CY 트리거, 8바 동안 `dropEnv` 1→0 선형 감쇠로
두 베이스라인 컷오프 +1옥타브·Drive +0.2를 곱해 준다. 판정·점수 없음. 빌드업은 레지던트가 한다.

### 2.6 보이스 (위임 파일)

- `voice.go`/`filter.go` — 베이스라인: 톱니/사각 오실레이터(PolyBLEP 또는 위상 누산+단순 안티에일리어싱), 다이오드 래더 4폴 근사(레조넌스 루프에 HPF), 앰프·필터 디케이 엔벨로프, 액센트(레벨+엔벨로프 깊이+짧은 디케이), 슬라이드(스텝 길이 동안 지수 포르타멘토), 게이트 오프 시 릴리즈 8ms.
- `drums.go` — BD(브리지드-T 근사: 사인 피치 스윕 + 클릭), SD(톤 2개 + 노이즈 밴드패스), CH/OH(6비트 양자화 금속 노이즈 → HPF, OH는 긴 디케이), CP(노이즈 4연타 + 리버브 꼬리 근사), CY(금속 노이즈 + 밴드 2개, 긴 디케이). Tune은 보이스별 의미(BD 피치, SD 톤, 햇 HPF, CP 밀도, CY 밴드).
- `fx.go` — 드라이브 → 템포 딜레이(점8분, 스테레오 핑퐁, 최대 1초 버퍼 = 48000×2 float32 New에서 할당) → 사이드체인 컴프(BD 트리거 신호 입력) → 마스터 → 소프트클립.

## 4. 호스트 프로토콜 (`app/web/processor.js` ↔ `host.js`)

- main→worklet `{t:'cmd', at, k,a,b,c,d,v}` — `at`은 블록 인덱스(0=즉시). 워클릿은 정렬 큐에 넣고 `block ≥ at`인
  첫 블록 시작에 적용. 호스트는 항상 `at = 추정 현재 블록 + 2`로 보내 로그의 블록이 실제 적용 블록과 같게 한다.
- `{t:'reset', seed}` · `{t:'state:set', bytes}` · `{t:'state:get'}` → `{t:'state', bytes, block}`.
- worklet→main `{t:'tick', block, step, bar, flags, peak, ctxTime}` — 4블록마다, flags는 누적 OR. 호스트는
  `ctxTime↔block` 선형 대응으로 `blockNow()`를 추정한다.
- 호스트 API(`window.jd`): `start()`(제스처 뒤) · `cmd(c, author)`(로그 기록 포함) · `state()` · `tick()`(최신 스냅샷)
  · `replay(fromBlock, toBlock)`(키프레임 복원 + 델타 재전송, 3·2·1 뒤) · `log()` · `telemetry(ev, data)`.
- 텔레메트리 이벤트(첫 커밋부터): `first_tap`, `first_sound_ms`, `first_knob_ms`, `exit_60s`, `drop`, `replay_used`,
  `seed_open`, `worklet_error`. `?kind=telemetry`로 기존 Worker에 POST(세션당 1회 배치 + `visibilitychange`에 flush).

## 5. 세션 (`session/`)

- `Entry{Block uint32; Author uint8; Cmd engine.Cmd}` · `Log{Seed uint32; Entries []Entry; Keyframes []Keyframe}` ·
  `Keyframe{Block uint32; State [engine.StateSize]byte}` — 호스트가 16바마다 요청해 넣는다.
- `SeedFromWord(s string) uint32` — NFC·소문자·공백 제거 후 FNV-1a 32. 빈 문자열은 0x9E3779B9.
- `EncodeURL(word, log) string` / `DecodeURL(s) (word, log, error)` — 스텝 경계 양자화, varint+델타, base64url.
  예산: 5분 손 조작 합성 로그(노브 200회 × 중간값 20)가 **2000자 이하**. 초과 시 연속 SetParam 압축(같은 파라미터의
  중간값을 초당 8개로 감량)을 적용하고 실측을 `docs/`에 남긴다.
- `cmd/jdsess`: 합성 로그 생성 → URL 길이 출력(게이트).

## 6. 레지던트 (`resident/`)

- `New(seed uint32, vibe Vibe) *Resident` · `Tick(in Input) []engine.Cmd` — Input{Bar, Step, Now(초), Pomodoro}. 바 경계에서만 결정.
- 생성기: 스케일(마이너 펜타·프리지안·블루스 중 시드 선택) · 밀도 · 휴지·슬라이드·액센트 확률 · 옥타브 점프. 드럼은 킥 골격 + 시드 변주.
- 에너지 곡선: 인트로→빌드→드롭→브레이크다운, 주기 4~8분(시드 파생), 매 주기 시드 파생. 단계별 목표 파라미터 대역과
  드럼 밀도. 노브 이동은 스텝마다 보간(1바에 8회 SetParam까지).
- 바이브: DeepFocus(120, 드럼 얇게, 컷오프 낮게) · Rush(135, 풀 드럼) · Lofi(비트크러시 대신 Drive 낮게+Delay 높게, 느린 템포).
- 포모도로: `Pomodoro{Focus, Rest 분}` 기본 25/5, 첫 세션 5분 데모. 집중 종료 16바 전 빌드, 종료에 Drop, 휴식은 브레이크다운.
- MANUAL 잠금: `Lock(ParamID)` 뒤 그 파라미터는 건드리지 않는다. `Resume()`·포모도로 경계에서 해제.
- `Hand() (param ParamID, active bool)` — 캐릭터 손 애니메이션 타깃(마지막으로 움직인 파라미터, 1바 유지).

### 12.1 엔진 계약(리드 골격 커밋 — 구현은 라운드 P2-engine)

- **도수 표기**: 베이스 패턴 `note = octave*7 + degree`(0..MaxNote 36, octave 0..5). degree 0 = 현재 마디 코드의 루트,
  1..6 = 그 위 조성 음계 음(0·2·4 = 코드 톤, 6 = 7th). `engine.ResolveNote(keyRoot, chordDeg, note)` → C1 기준 반음
  (0..MaxSemis 48). 조성은 자연 마이너 하나, 루트 0..11. 패턴은 리듬·윤곽, 코드 트랙은 화성 — 코드를 바꾸면 패턴이 따라온다.
- **Cmd 추가**(`engine/cmd.go`): `SetKey A=root` (다음 바 경계) · `SetChord A=bar(0..7) B=deg(0..6) C=ChordSeventh` (즉시) ·
  `BassMode A=part B=ModeBass|ModeArp|ModeChord C=DirUp|DirDown|DirUpDown` · `Transport A=1 재생/0 정지`.
- **모드 의미**: BASS = 패턴 도수 그대로. ARP = 게이트된 스텝마다 코드 톤(루트·3·5[·7])을 방향 순서로 하나씩, 옥타브는
  패턴 note/7, 도수 필드는 무시. CHORD = 3음 패러포닉 스탭(오실레이터 3개 → 필터 1개): 7th 없으면 루트·3·5, 있으면 3·5·7.
  슬라이드·액센트 플래그는 모든 모드에서 유효(ARP의 슬라이드 목표 = 다음 아르페지오 톤).
- **트랜스포트**: 정지 = 스텝 위치 동결·두 베이스 노트오프·드럼과 딜레이 꼬리는 자연 감쇠(Render는 계속). 재생 = 현재 바 유지,
  다음 Render에서 스텝 0부터. 기본 playing = true. 정지 중 FlagBar 없음 → 레지던트는 쉰다.
- **상태 v2**(`engine/state.go`): magic 'J','2', StateSize 696. 679 key · 680..682 mode|dir<<2 · 682 playing · 683..691 코드 8.
- **초기 상태**: keyRoot = seed 유도(0..11), 코드 트랙 기본 `i i VI VII | i i iv v`, 모드 BASS. genInitialPatterns는 도수로 생성
  (루트 0.5·코드 톤 0.3·경과음 0.2 가중) — 첫 바부터 조성 안의 소리.
- **워클릿 export 추가**: `jd_key` `jd_chord(bar)→deg|flags<<8` `jd_mode(part)→mode|dir<<8` `jd_playing` `jd_sync`(섀도 엔진용
  바 경계 대기값 반영 — `Engine.SyncPending`).
- 게이트: 기존 전부(무할당·FMA 0·결정론) + 도수 해석·ARP 순서·CHORD 톤·정지/재생 단언. 해시 게이트는 **재기준**(도수 의미 변경으로
  기존 해시는 무효 — 네이티브 == node == chromium == webkit 일치만 본다).

### 12.2 호스트(라운드 P2-host)

- **섀도 엔진**: host.js가 같은 engine.wasm을 메인 스레드에 하나 더 인스턴스화(`jd_init(seed)`), 렌더는 하지 않고 `cmd()`마다
  같은 `jd_cmd`를 적용한다. `jd.param/bassStep/drumStep/muted/slot/keyRoot/chord/mode`는 전부 섀도에서 읽는다(손으로 쓴
  미러 배열 폐기). 바 경계 틱(FlagBar)마다 `jd_sync`. 제스처 전에도 시드가 고른 키·초기 패턴을 UI가 그대로 보인다.
- tick에 `playing`(워클릿 tick 메시지 필드 추가). `jd.hint(state)` → DOM 캡션(문구는 index.html이 소유, 리드 저작).
- 개발 버튼(replay·clean·share·Send report·seed)은 `?dev=1`에서만 표시. 텔레메트리 본문은 `text/plain` Blob(프리플라이트 회피 —
  Worker는 본문을 JSON.parse하므로 무관), 이탈 시 전송이 Worker에 실제 기록되는지는 리드가 `tools/reports-pull.sh`로 확인.
- 제스처 전 시각 구동: Go(main.go)가 `!Tick.Started`면 기본 템포(130 BPM, 스텝 115.4ms)로 가짜 스텝·바 시계를 만들어 뷰에 준다.
  첫 탭 = "소리 켜기"(캡션 문구). 시작 시 실제 틱으로 교체(위치 점프 허용).
- 첫 접촉 캡션 상태기계(main.go): 1 탭 전 → 2 시작 후 20초 또는 기기 탭까지 → 3 기기 뷰 첫 진입 후 첫 조작까지 → 0.
- MANUAL 자동 복귀: 마지막 노브 조작 후 30초 무접촉이면 `Resume()`. 사람의 SetChord/BassMode/SetKey는 `LockHarmony()` —
  세션 내 영구(레지던트가 다시 쓰지 않는다).

### 12.3 기기 뷰(라운드 P2-device)

- play 버튼 = PLAY/STOP 토글(`Transport`), 라벨 "PLAY", 재생 중 lit. rec 버튼 = DROP(기존 펄스 연출 이전). RESUME 버튼 제거
  (`ResumeTapped()`는 항상 false로 남겨 호출자 호환).
- 코드 트랙 띠 `layout.chord_track` [22,103,675,27]: 8셀, 로마 숫자(i ii III iv v VI VII, 7th는 "7" 접미), 현재 마디(Tick.Bar&7)
  셀 채움 colLEDMid. 셀 탭 → 선택기 모드: 같은 띠에 7도수 셀 + "7" 토글, 탭하면 `SetChord`(Human) 후 닫힘, 띠 밖 탭은 닫기.
- 베이스 B 표시창 탭 → 모드 순환 BASS → ARP UP → ARP DN → ARP UD → CHORD → BASS(`BassMode` Human). 표시창은 모드 문자열.
- 하단 표시창: `KEY Am - BPM 120 - BAR 3 - BUILD`(MANUAL 잠금 중이면 BUILD 대신 MANUAL). 키 이름 표 C C# D … B + "m".
- 스텝 추적등은 기존(fx LED 현재 스텝) 유지.
- 라인 미터(P3-meters): 레벨 원본은 `Tick.Levels`(파트 순 블록 피크, 프리 FX)·`Tick.Peak`(마스터). 매핑
  vu = (20·log10(level)+36)/36(−36dB→0, 0dB→1, 음수·NaN→0, 1 초과→1), 밸리스틱 어택 즉시·릴리스 4/s.
  베이스 A·B 표시창 하단 4px 띠에 12세그먼트(세그먼트 폭 = (창폭−2×2 여백−11×1 간격)/12, 바닥에서 2px 위,
  세그먼트 0..9 `colLCD` α0.9·10..11 `colLED`), 하단 표시창은 같은 세그먼트 규칙 20세그먼트(높이 3px, 마스터).
  띠는 표시창 문자열 캐시 밖 화면에 매 프레임 — 텍스트는 세로 중앙에서 베이스 −2px·하단 −1px(띠 회피, slot별
  오프셋). 드럼 패드는 탭 lit과 합성 α = max(탭 0.18, 0.12+0.5·vu) 상한 0.62 + 좌상단(+6,+6) 반지름 4 LED 점
  (`colLED`, α = vu, 레벨 0이면 미그림). 구 호스트(Levels 전부 0)는 미터 완전 소거(밸리스틱 잔상 포함).
- 스크롤 랙(P4-scroll): 레이아웃 v3(720×1800)에서 화면(720×1280)은 랙의 맨 위 창이다. Draw 본문을 전부
  `rack` 오프스크린(레이아웃 크기, New에서 1회)에 그리고 `scrollY`만큼 올려 blit 1회(SubImage·Clear 없음 — 둘 다
  할당/비용이라). scrollY 상한 = `Size[1] − LogicalH`(v3 = 520). 제스처 우선순위: 컨트롤(노브·패드·버튼·코드
  띠·표시창·이름판) 히트가 이기고, 어느 것도 아닌 눌림 = 빈 판 잡기 → 드래그가 스크롤(놓으면 직전 프레임 dy로
  관성 ×0.9/프레임, |v|<2px 정지, 경계 도달 즉시 정지 — 반발 없음). 노브에서 시작한 드래그는 끝까지 노브.
  동시 두 빈 판 포인터는 첫 것만. 휠은 `ebiten.Wheel()`을 Update 안에서 직접(60px/틱, 관성 없음 — 브라우저가
  이미 트랙패드 관성을 흘려준다). 인디케이터: 우측 가장자리 4px, 길이 = 1280²/1800, y 비례, 스크롤 중 + 1초만.
  좌표 계약: 화면 y + scrollY = 레이아웃 y 변환의 단일 소유자는 press()의 히트 판정이고, 제스처 델타(노브
  드래그·스크롤)는 화면 좌표계로 잰다 — 사본을 레이아웃 좌표로 만들면 매 프레임 scrollY가 델타에 끼어 들어
  잡은 채 드래그가 절반씩 죽는다(실측: 2연속 이동 프레임에서 두 번째 dy만 반영). 높이 ≤ 1280 레이아웃은
  scrollMax 0 — 스크롤 없음·인디케이터 없음. 실측: 프레임 p95 0.30ms(랙 blit 포함, 도입 전과 동일),
  Update 무할당 유지(스크롤 상태·관성 중·잡은 채 전부 0).

### 12.4 레지던트(라운드 P2-resident)

- 세션 시작 바에 `SetKey`(seed 유도 — 엔진 초기값과 같게 `seed % 12`), 사이클 시작마다 진행표에서 8마디 코드를 골라 `SetChord`×8.
  진행표(마이너, 도수): `i i VI VII | i i iv v`, `i VI III VII | i VI III VII`, `i iv VII III | VI ii v i`, `i i i i | VI VI VII VII`,
  `i VII VI VII | i VII VI v`, `i v VI iv | i v VI VII`. Drop 페이즈는 7th를 iv·v·VII에 붙인다.
- 패턴 음은 도수로: 루트 0.5·코드 톤 0.3·경과음 0.2, 옥타브 점프 0.1 유지. B 모드는 페이즈로: Intro BASS(밀도 0.4) → Build ARP UP
  (밀도 0.9) → Drop ARP UD(밀도 0.9, 7th) → Breakdown CHORD(스텝 0·8·12 스탭). `LockHarmony()` 뒤엔 SetKey/SetChord/BassMode를 내지 않는다.

### 12.6 공유 URL = id만 (사용자 결정 2026-09-06)

- URL에는 세션 id(base62 10자)만 싣는다: `?s=<id>`. 로그·상태는 Worker(`cf/worker.js`) `POST /sessions`에 저장하고 `GET /sessions/<id>`로
  읽는다(불변, 1년 캐시, 링크를 가진 누구나 읽기, 쓰기는 허용 오리진만, 본문 ≤256KB). KV 네임스페이스 SESSIONS. 배포 완료·스모크 통과
  (2026-09-06). 무료 KV 쓰기 한도 1,000회/일 — 공유 버튼 남용은 클라이언트 쿨다운(10초)으로 막는다.
- 저장 본문: `{v, seed, word, log: <session 이진 페이로드 문자열>, state: <공유 시점 키프레임 base64>, meta}`. session 패키지의 인코딩은
  그대로 저장 페이로드로 쓴다 — URL 예산 감량 사다리는 저장에는 필요 없으므로 **감량 0단계(무손실)** 로 저장한다. 열 때는 state로 즉시
  이어 듣고, 로그는 리플레이용.
- 앱 배선(share → POST → id, `?s=<id>` → GET → 재생)은 host 라운드 병합 뒤 소라운드 P2-share에서. 인라인 페이로드(`v2.` 접두사)는 접두사로
  구분해 당분간 같이 받는다.

### 13.2 신호 흐름(engine/fx2.go — 새 파일, fx.go 체인은 그대로)

```
bassA' = mul32(bassA, lvlA)   bassB' = mul32(bassB, lvlB)      (레벨은 Level() 미터보다 앞 — 미터는 레벨 반영값)
dry   = fx.process(bassA'+bassB', drumMix, bd, drop)            (기존 체인 그대로 → L,R)
revIn = Σ_p mul32(part_p, revSend_p)         part = bassA', bassB', drums.last[0..5]
choIn = mul32(bassA', choA) + mul32(bassB', choB)
L = dry.L + revL + choL ,  R = dry.R + revR + choR             (센드가 하나라도 >0인 버스만 더한다)
최종 소프트클립은 fx.process 안에 있으므로 리턴은 클립 뒤에 더해진다 → 리턴 합의 상한을 0.8로 잡고 마지막에 한 번 더 outClip(L), outClip(R)을 통과시킨다(|out| ≤ 0.9903 유지).
```

- **리버브**: Schroeder — 프리딜레이 20ms → 병렬 콤 4(기준 길이 1557·1617·1491·1422 샘플, 길이 = 기준×(0.6+0.8·size), 피드백 경로에 1폴 LP(damp)) → 직렬 올패스 2(225·556, g 0.5). 스테레오는 R 채널 콤 길이 +23 샘플. 버퍼는 New 시 고정 배열(최대 길이 = 기준×1.4 올림). 순수 Go·`math` 금지 규칙 그대로(계수는 `exp2`·다항으로).
- **딜레이 센드**: `delayIn = Σ_p mul32(part_p, delaySend_p)`(프리 드라이브·포스트 레벨). fx.go 체인의 딜레이 입력 `s`를 이 값으로 바꾸는 최소 diff(process에 인자 하나 추가). 리턴 경로(핑퐁·피드백 LP·DELAY 노브 = mix/fb)는 그대로. 센드가 전부 0이면 종전처럼 바이패스.
- **페이저**(사용자 요청)는 Phase 3 장치 그래프의 단품 이펙터로(§14.2 4번) — fx2 패널에 노브 자리가 없고, 케이블로 어디에나 끼우는 것이 본래 용법이다.
- **코러스**: 기준 지연 12ms, 삼각 LFO(위상 누산기, 곱셈·덧셈만) L/R 위상 90° 차, 깊이 0..6ms, 선형 보간(`mul32`), 피드백 없음. 버퍼 1024 샘플.
- 비용 게이트: `go test -bench Render` ns/블록이 Phase 2 대비 +60% 이내(센드 켠 상태로 측정), 워클릿 stalls 회귀 없음.
- 상태 v3(magic 'J','3'): params 영역 2×51 = 102바이트 → 뒤 오프셋 전부 +36, StateSize 732. v2 이하는 거부(리플레이는 로그로 재현하므로 저장 세션은 안전).

## 14. Phase 3 로드맵 — 랙 그래프·악기 확장·샘플러·뒷면 케이블 (2026-09-06, 사용자 방향)

사용자: "악기들도 많이 늘리고 싶고, 가능하면 샘플러도, 랙에 추가할 악기들도, 악기를 어떤 이펙터로 어떻게 연결할지 랙 뒤편 케이블 연결도 에뮬레이션."
Reason식 랙이 목표다. 지금 엔진은 **고정 체인**(베이스 2 + 드럼 6 → FX)이라 이대로는 악기를 하나 늘릴 때마다 sample()·상태·UI·레지던트를 손으로 늘려야 한다. Phase 3의 본체는 **엔진을 장치 그래프로 바꾸는 것**이고, 악기·샘플러·케이블은 그 위의 항목이다.

### 14.1 장치 그래프(엔진)
- `Device` 계약(순수 Go 인터페이스 아님 — 인터페이스 박싱은 핫 루프 금지 규칙에 걸리므로 **종류별 고정 배열 + 종류 switch**): `init(seed)`, `setParam(k, q)`, `trigger(...)`, `process(in []float32, out []float32)`, 포트 표(입력 n·출력 m, 모노/스테레오), 상태 직렬화(길이 고정).
- 랙 = 장치 슬롯 고정 배열(예: 최대 16)과 **케이블 표**(src 장치·포트 → dst 장치·포트, 게인). Cmd 신설: `AddDevice(slot, kind)`, `RemoveDevice(slot)`, `Connect(srcSlot, srcPort, dstSlot, dstPort, gain)`, `Disconnect`. 렌더는 케이블 표에서 유도한 위상 순서(Connect 시점에 계산 — 핫 루프 밖, 순환은 거부)로 블록 단위 처리. 버스 버퍼는 New 시 고정.
- 지금의 Phase 2.5 센드(§13)는 이 모델의 첫 인스턴스로 읽는다: 파트 출력 8 → 리버브 입력(게인 = 센드), 베이스 2 → 코러스 입력, 리턴 → 마스터. **fx2 라운드는 계약을 바꾸지 않되 코드를 "포트와 버스"로 짠다**(리버브·코러스가 `process(in, out)` 형태) — Phase 3에서 그대로 장치로 승격.
- 결정론·해시 게이트는 유지: 같은 seed·같은 Cmd 이력(케이블 포함) → 같은 바이트. 기본 랙(현재 구성)의 해시는 불변.
- 상태: 장치별 고정 길이 블록 + 케이블 표. 세션 URL/KV 저장은 로그 재생이라 자동 반영, 키프레임 상태는 v4.

**구현(P5-graph, 리드 직접 — 2026-09-06 저녁, 설계 코어라 위임하지 않음)**: `engine/rack.go`. 장치 = (DeviceKind, 인스턴스) — 종류별 고정 배열을 Engine이 소유(Bass 2·Drums 1·Fx 1·Reverb 1·Chorus 1·Main 1). 슬롯 16·케이블 64, 케이블은 dst 순 정렬(같은 dst 안은 삽입 순 = 합산 순), 위상 순서는 Kahn(준비된 슬롯 중 번호 최소 — 기본 랙 순서가 옛 고정 체인 순서 0..6). **포트 합산 규칙**: 첫 케이블 대입·이후 덧셈("0에 더하기"가 −0을 지워 dry 바이패스 비트 동일성을 깬다), live=false(입력 포트가 있는데 게인>0 입력 케이블이 없는 장치 — 옛 revOn/choOn) 장치의 출력 케이블은 건너뛴다. 핫 루프는 recompute가 만든 활성 케이블 목록만 돈다. 게인 단일 소유자: 결속(bind<NumParams)이면 파라미터에서 유도(RevMix/ChoMix ×0.8, 센드 q) — 기본 랙의 센드·리턴 28케이블은 전부 §13.1 파라미터 결속이라 노브가 그대로 케이블을 돌린다. mixBus는 소멸(fx2.go는 reverb·chorus 장치만). 실측: **기본값 30초 해시 cacd0efe… 불변**(네이티브·node·chromium 셋 동일 — 상수를 바꾸지 않고 통과), FMA 0, Render·Apply·상태 왕복 무할당, 전 패키지 테스트 통과. 비용: 네이티브 ns/블록 35.5k → 46.7k(+31% — 샘플 단위 장치 루프·케이블 합산 오버헤드, wasm-node 31.4k), 워클릿 34,779 → 41,866B(gzip 15.8KB). 블록 단위 처리로 되돌리는 최적화는 백로그(예산 2.67ms 대비 여유). 게이트 rack_test.go 10종(기본 랙 구성·Add/Remove 정규화·Connect 규칙·순환 거부·표 가득·결속 유도·재배선 가청·상태 v4 왕복+오염 재정규화·무할당·파트 제거 레벨 0).

### 14.2 악기 후보(우선순위 제안)
1. **폴리 신스**(코드 트랙을 직접 연주 — 지금 CHORD 모드의 3오실레이터 패러포닉을 독립 장치로, 4~6보이스, 필터·엔벌로프) — 레지던트가 이미 코드를 알고 있어 자동연주가 바로 된다.
2. **샘플러**(원샷/루프, 피치 = 도수 해석, 슬롯 8, 슬롯당 최대 2초 모노 48k = 96K 샘플 → 8슬롯 3MB, New 시 고정 할당 — `-gc=leaking` 상한 안). 소리 소스는 ① 내장 팩(CC0/자체 제작, 레포 자산) ② 사용자 업로드(브라우저 디코드 → 48k 리샘플 → 워클릿 메모리 복사; 세션 공유 시 샘플 바이트도 KV/R2에 — 256KB 한도를 넘으므로 별도 저장 경로). **① 먼저.** 샘플 데이터는 해시 입력이 된다(같은 팩이면 같은 바이트).
3. **드럼 샘플러 킷**(위 샘플러의 6패드 변형 — 기존 합성 드럼과 병존).
4. **노이즈/텍스처 장치**(비 소리·테이프 노이즈 — 방 분위기와 연결), **페이저·필터·딜레이 단품 이펙터**(케이블로 어디에나 — 페이저는 사용자 요청 2026-09-06).
**폴리 리드 설계(P5-poly, 2026-09-06 저녁)**: DSP `engine/poly.go`(GLM 라운드 P5-poly-dsp — 4보이스 × 디튠 톱니 3(슈퍼소), 보이스별 다이오드 래더, 앰프 어택/릴리즈·필터 디케이 엔벌로프, 로컬 파라미터 k 0..7 = Cutoff Reso EnvMod Attack Decay Release Detune Level, 출력 유리식 소프트클립 ≤ 0.99026). 엔진 결합(리드): `KindPoly`(입력 0·출력 1, 인스턴스 1) — 기본 랙 슬롯 7, 케이블 Poly→Fx 직결 입력(1.0)·Fx 딜레이 입력(0.55)·Reverb(0.35)·Chorus(0.3) 전부 비결속(폴리 센드 노브는 아직 없다 — UI 라운드에서 DeviceParam/케이블 게인 바인딩). 시퀀서: 슬롯 스텝 패턴(`DeviceStep`) 게이트 스텝마다 그 마디 코드 톤(3 또는 4)을 보이스 0..3에 배정(`ResolveNote(key, deg, oct*7+ChordToneDeg)` — 옥타브는 패턴 note/7), 게이트 없는 스텝은 전 보이스 릴리즈, **타이**(StepGate|StepSlide) 스텝은 유지(재트리거 없음 — 패드). Transport 정지 → allOff. 레지던트 연주법(`resident/poly.go`): 페이즈 진입 바에 패턴 16 + 음색 5(DeviceParam) — Intro/Breakdown 패드(스텝 0 게이트 + 타이 15, 옥타브 2), Build 오프비트 8분(2·6·10·14, 옥타브 3), Drop 트랜스 게이트(11게이트·액센트 4, 옥타브 3, 컷오프 0.7·디튠 0.6). 음은 고르지 않는다(엔진이 코드 트랙에서 읽는다) — 화성 잠금과 무관. 미터·패널 그림·노브는 후속(P5-poly-ui). 기본 랙에 들어가므로 기본값 해시가 바뀐다(재기준 1회 — 바이트 변경은 이 하나).

각 악기 = 엔진 장치 + 패널 그림(tools/rack 파이프라인) + 레이아웃 + UI 바인딩 + **레지던트 연주법**(노동요 오토파일럿이 그 악기를 어떻게 다루는지) — 마지막 항목이 가장 비싸다. 레지던트가 모르는 악기는 "사용자가 직접 연주하는 악기"로 시작한다.

### 14.3 뒷면 케이블 뷰(UI)
- 기기 뷰 상단 이름판 탭 → 방, **길게 누르기(또는 FLIP 버튼) → 뒷면**. 뒷면은 같은 랙 좌표에 장치별 잭 패널(입력 잭 왼쪽·출력 잭 오른쪽, 라벨은 앱 폰트), 케이블은 잭↔잭 베지어(늘어짐 = 거리 비례, 색 = 신호 종류)로 앱이 그린다(그림이 아니라 코드 — 케이블은 상태에 따라 변하므로).
- 조작: 출력 잭에서 드래그 → 입력 잭에 놓으면 Connect, 케이블 중간을 잡아 빈 곳에 놓으면 Disconnect, 케이블 탭 → 게인 노브(작은 팝업). 스크롤은 앞면과 같은 규칙.
- 뒷면 패널 그림은 fal.ai로 한 장(잭·나사·통풍구·라벨판 — 앱이 잭 위치를 layout으로 소유).
- 게이트: 케이블 표 ↔ 그려진 베지어 수 일치, 잭 히트 영역 ≥ 28px, 순환 연결 시 거부 피드백(잭 붉게 1회).

### 14.4 순서
